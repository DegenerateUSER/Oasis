# Fast local verification

Oasis development checks must not silently execute the benchmark corpus. Use tiny
fixtures and bounded checks for everyday development. Existing benchmark CSVs are
historical data, not results regenerated by this change.

## Setup and hard-bounded feedback loop

```sh
uv sync --locked
uv run python scripts/quick_check.py
# A narrower loop:
uv run python scripts/quick_check.py tests/test_runner_safety.py tests/test_scope.py
```

The helper terminates the pytest process tree after at most 120 seconds. It does
not invoke the corpus batch runner. Provider-download integration tests are skipped
unless explicitly enabled in plain pytest. `TMPDIR` controls the temporary fixture
location; set it to the environment's scratch directory where appropriate.

## Tiny real-engine example

```sh
uv run pytest -q tests/test_smoke_engine.py
```

This creates disposable Git repositories using the built-in `terraform_data`
resource: no cloud resources or downloaded providers. It checks that a weak
assertion permits a count mutation, a strengthened assertion kills it, overridden
variable defaults are excluded, and original source bytes are restored. Terraform
and OpenTofu cases skip explicitly when their binaries are unavailable.

## Offline policy comparison

Install tfsec separately from its official distribution and verify its checksum.
Oasis does not auto-download or auto-update the scanner.

```sh
TFSEC_BIN=/path/to/tfsec uv run pytest -q tests/test_scanner.py
uv run python scripts/compare_scanner.py /path/to/clean-small-repo \
  --output-dir /path/outside/repo/comparison \
  --tfsec /path/to/tfsec --operator MUT-SEC-002 \
  --max-mutants 3 --budget-seconds 60
```

The scanner runs with module downloads disabled. Raw stdout/stderr, timings,
repository revision and individual mutant findings are preserved in the output
JSON. Same-file line overlap is only an association; it is not proof that a policy
check and a test assertion express the same requirement. Scanner findings are not
mutation-test kills. Optional existing test results are associated only when
catalog version, source hash and exact mutation identity match.

## Optional cached-provider schema validation

```sh
OASIS_AWS_PLUGIN_DIR=/existing/provider/mirror \
OASIS_AWS_VERSION=5.100.0 \
uv run pytest -q --run-provider-tests tests/test_acl_schema.py
```

This uses an explicitly supplied local provider mirror and runs only init and
validate against a disposable configuration. It neither applies resources nor
requires cloud credentials. Do not run the older provider-download tests as part
of the ordinary development feedback loop.

## Dataset checks without repository execution

```sh
uv run python scripts/audit_dataset.py /path/to/results.csv --output /path/to/audit.json
```

The auditor validates duplicate identities, statuses, conclusive-result validation
and survivor classification, and separates module-baseline records from generated
mutants. Missing scores remain null, not zero. This command reads CSV data only;
it does not initialize or test any repository.

## Safety and interpretation

- Run mutation tests only on clean tracked/index state or an isolated worktree.
- Restoration preserves owned file bytes and permissions without resetting the
  entire repository or Git index. Python finally blocks do not survive SIGKILL or
  power loss; abandoned edits are refused as dirty state on the next invocation.
- Remote/vendored modules and unresolved scope are disclosed rather than guessed.
- Static reference classification is not runtime execution coverage.
- No-op checks prove specific override cases, not general semantic equivalence.
- Unexecuted, invalid, no-op, timeout, zero-execution and unknown-error records are not scored.
- Runner uses native engine JSON diagnostic summaries; diagnostic detail cannot
  impersonate an assertion failure. A passing exit must also show executed tests.
- Hidden `TF_CLI_ARGS*` inputs are rejected. Put supported flags explicitly in
  `--test-cmd` so discovery and execution select the same tests.
- Completion manifests checksum CSV, summary and raw evidence files. Missing or
  altered evidence prevents reuse. Runs made with unresolved external input
  context remain non-resumable even if those inputs are later removed.
- Changed operator catalogs require fresh results; never silently reuse old CSVs.
